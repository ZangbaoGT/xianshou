# 实验设计：16 字节事件能否让 B 更早停下？

## 假设

在 B 的视觉被遮挡（模拟盲区）时，A 的 16 字节事件包能让 B 比“只有自己”更早停止，且带宽远低于视频流。

- **H1**：有事件通信时，A 检测到行人 → B 停止的延迟显著更短。
- **H2**：有事件通信时，B 在安全距离内停下的成功率更高。
- **H3**：事件通信的带宽 ≤ 32 B/s（稳定时接近 0），比视频流低 2 个数量级。

## 条件

| 条件 | A | B | 说明 |
|---|---|---|---|
| A（基线） | 在场但不发事件 | 蒙眼，向前 | 测量 B 自己的反应（它看不见） |
| B（实验） | 在场，发 16B 事件 | 蒙眼，向前 | 测量 A 的事件带来的提前量 |

> “蒙眼”用一块不透明布盖住 B 的相机，模拟货架/拐角后的盲区。两组都蒙眼，隔离“A 的事件”这一个变量。

## 场地与道具

- 2×3 m 平整地面；B 从起点直线前进，速度约 0.15 m/s。
- A 放在 B 侧后方 1.5–2 m，相机覆盖 B 的盲区。
- 行人用 1 个软障碍/泡沫箱代替（避免真人风险），从 B 的侧前方 1.2 m 处进入。
- 地面贴一条停止线/安全线；B 的“安全”定义为：在障碍进入其路径前停止，且间距 ≥ 0.3 m。

## 流程（每组 10 次，共 20 次）

1. B 蒙眼，站在起点；A 开机，看板开始记录。
2. 随机延迟 2–5 s 后，操作者把障碍从 B 的盲区推入。
3. A 的帧差/LIF 触发，发 16B；B 收到后 STOP 1 s。
4. 记录：
   - `t_detect`：A 的变化分数首次超过阈值的时间。
   - `t_send`：A 发出包的时间。
   - `t_recv`：B 收到包的时间。
   - `t_stop`：B 进入 STOP 的时间。
   - `d_min`：B 与障碍的最小间距（目测/卷尺）。
5. 复位，重复。两组交替进行，避免顺序效应。

## 指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 反应时间 | `t_stop - t_detect` | 实验组比基线早 200–300 ms |
| 成功率 | `d_min ≥ 0.3 m` 的次数 / 10 | 实验组 ≥ 8/10 |
| 带宽 | 发送字节数 / 时间 | ≤ 32 B/s |
| 误报 | 无障碍时 A 发事件的次数 | ≤ 1/10 |
| 丢包 | B 未收到 / A 发送 | 记录并报告 |

## 预期结果

- 基线：B 蒙眼，基本无法在安全距离内停下（成功率 0–2/10）。
- 实验：B 收到事件后 100–300 ms 内停下，成功率 8–10/10。
- 带宽：稳定时 0 B/s，每次事件 16 B；按 1 次/秒算，约 16 B/s。
- 对照视频流的 640×480@10 Hz（约 3–10 Mbps），低 2–3 个数量级。

## 数据与复现

- `logs/a.csv`：`t, score, membrane, sent, bearing_deg, distance_cm`
- `logs/b.csv`：`t, recv, src_id, bearing_deg, distance_cm, confidence, state`
- 看板：`streamlit run dashboard.py`
- 仿真：`python sim_swarm.py`（生成 `logs/sim.csv` 和 GIF）

## 效度威胁

- **Wi-Fi 抖动**：用本地 5GHz 路由；记录 `t_recv - t_send`；目标 < 50 ms。
- **光照/背景变化**：A 固定、背景干净；阈值现场校准。
- **人为计时误差**：用同一台机器的时间戳；两组交替。
- **“B 其实能看见”**：布盖严；实验前用一次空跑确认 B 的相机全黑。
- **样本小**：20 次是 demo 规模；论文里扩到 50 次/组。

## 通过标准（现场）

- 至少 1 次完整的“A 看见 → 16B → B 停”的实机演示。
- 20 次对照数据可导出、可画图。
- 看板能实时显示脉冲、带宽、反应时间。
- 一段 60–90 秒的实机视频。
